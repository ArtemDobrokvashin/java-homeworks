1. Определения.

База данных - организованное хранилище информации, которое используется для организации, хранения и доступа к данным.

SQL (Structured Query Language) - язык запросов для управления базами данных: с его помощью создают, изменяют и удаляют таблицы и записи, а также выбирают нужные данные.

Первичный ключ (PRIMARY KEY) - столбец или набор столбцов, который уникально идентифицирует каждую строку таблицы. Не может быть пустым и не может повторяться.

Внешний ключ (FOREIGN KEY) - столбец, который ссылается на первичный ключ другой таблицы и связывает таблицы между собой. База не даст записать значение, которого нет в связанной таблице.

Индекс - служебная структура внутри БД, которая ускоряет поиск по столбцу. Работает как оглавление книги: вместо просмотра всех строк база сразу находит нужные.

Нормализация - процесс организации данных в БД: таблицы проектируются по правилам, которые устраняют избыточность, чтобы одни и те же данные не хранились в нескольких местах.

2. Реляционные БД хранят данные в таблицах (строки и столбцы) со строгой схемой, таблицы связываются через ключи. Примеры: PostgreSQL, MySQL, H2, Oracle.

Нереляционные (NoSQL) не используют табличную схему. Данные хранятся в виде пар ключ-значение, JSON-документов или графов. Примеры: Redis, Amazon DynamoDB, Riak, Oracle NoSQL.

3. Первая нормальная форма: в таблице нет дублирующих строк (определён первичный ключ), в каждой ячейке хранится атомарное значение, в столбце данные одного типа, отсутствуют массивы и списки.

4. Вторая нормальная форма: таблица находится в 1NF, имеет ключ, и все неключевые столбцы зависят от полного ключа. Для составного ключа это значит, что данные нельзя узнать, зная только половину ключа. Пример: серия и номер паспорта по отдельности могут совпадать у разных людей, но вместе - уникальная комбинация.

5. Третья нормальная форма: в таблице нет транзитивных зависимостей - неключевые столбцы не зависят от других неключевых столбцов. Пример: в таблице заказов не хранят итоговую сумму, потому что она вычисляется из цены и количества.

6. Связи между таблицами:
   Один к одному (1:1) - один объект соответствует ровно одному объекту другой сущности. Пример: сотрудник и закреплённая за ним служебная машина.
   Один ко многим (1:N) - один объект соответствует нескольким. Пример: артист и его альбомы, кабинет и сотрудники в нём.
   Многие ко многим (M:N) - нескольким записям одной таблицы соответствуют несколько записей другой. Пример: треки и плейлисты. Реализуется через промежуточную таблицу с двумя внешними ключами.

7. JOIN - присоединение одной таблицы к другой в запросе по условию совпадения столбцов (ON).
   INNER JOIN - возвращает только строки, у которых есть совпадение в обеих таблицах.
   LEFT JOIN - возвращает все строки левой таблицы, к правой подставляет совпадения, если совпадения нет - NULL.
   RIGHT JOIN - наоборот: все строки правой таблицы, совпадения из левой.
