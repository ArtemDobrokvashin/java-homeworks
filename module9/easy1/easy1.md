

### Инкапсуляция и модификаторы доступа

Инкапсуляция — это защита внутреннего состояния объекта. Поля скрываются, а работа с ними идет через методы. Так мы гарантируем корректное использование объекта.

Модификатор доступа — ключевое слово (или его отсутствие), которое определяет, кто может обращаться к классу, полю или методу.

---

### Модификаторы в Java

| Модификатор | Доступ |
|-------------|--------|
| private     | Только внутри своего класса |
| (ничего)    | Внутри класса и пакета |
| protected   | Внутри класса, пакета и подклассов |
| public      | Откуда угодно |

Правило простое: делай всё как можно приватнее. Расширяй доступ только если нужно.

---

### Особые случаи

Топ-уровневый класс не может быть private или protected — только public или package-private (без модификатора).  
Но вложенный класс может быть private. Это удобно для служебной логики, которую не должны видеть извне.

Конструктор тоже может быть private. Чаще всего так делают в паттерне Singleton, чтобы запретить создание экземпляров напрямую.

---

### Интерфейсы

До Java 8 все методы в интерфейсе были абстрактными и публичными.  
С Java 8 появились default-методы — с реализацией по умолчанию. Они нужны, чтобы добавлять новые методы в старые интерфейсы без поломки существующего кода.

С Java 9 разрешили private-методы в интерфейсах — чтобы выносить общую логику из default-методов.

Protected в интерфейсах не разрешен, потому что интерфейс — это публичный контракт. У него нет «закрытых» наследников, как у классов.
