# Ответы на вопросы

## 1. Что такое наследование в Java? 

Наследование - это когда один класс **берёт методы и переменные** у другого класса. Тот, от кого берут, называется **родителем**, а тот, кто берёт - **дочерним классом**.

Пример:
```java
class Animal {
    void eat() {
        System.out.println("Ем");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Гав");
    }
}
```

Зачем это нужно?
- Чтобы не писать один и тот же код несколько раз
- Чтобы создавать логичную структуру: например, все животные едят, а собака ещё и лает
- Чтобы можно было использовать объект дочернего класса там, где ожидается родительский (это полиморфизм)

## 2. Что значит переопределить метод?

Это когда в дочернем классе **переписываем метод**, который уже есть у родителя. При этом имя метода, параметры и возвращаемый тип должны быть **точно такими же**.

Пример:
```java
class Animal {
    void sound() {
        System.out.println("Звук");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Гав");
    }
}
```

Когда вызываем `sound()` у объекта `Dog`, сработает именно его версия.

Важно:
- Нельзя менять параметры или тип возвращаемого значения
- Можно сделать метод более открытым (например, из protected в public)
- Но нельзя сделать его более закрытым

## 3. Сколько "родителей" может быть у класса?

У класса в Java может быть **только один прямой родитель**. Это называется **одиночным наследованием**.

Но класс может:
- Реализовывать **несколько интерфейсов** (это не наследование классов)
- Наследоваться от класса, который сам наследуется от другого класса

Пример:
```java
// Один родитель
class Dog extends Animal { }

// Несколько интерфейсов
class Dog implements Runnable, Serializable { }
```

## 4. Что такое аннотация? Для чего нужна аннотация @Override? Что будет, если мы уберём данную аннотацию над переопределённым методом?

Аннотации - это как **метки** над кодом. Они не влияют на выполнение программы, но дают информацию компилятору.

`@Override` говорит компилятору: "Этот метод переопределяет метод из родительского класса".

Если убрать `@Override`:
- Код будет работать так же
- Но если допустить ошибку в имени метода (например, `sount()` вместо `sound()`), компилятор не заметит ошибки
- С `@Override` компилятор сразу скажет: "Этого метода в родителе нет!"

`@Override` - как страховка от ошибок.

## 5. Какие особенности есть у класса Object?

`Object` - это **базовый класс для всех классов** в Java. Даже если написать `extends Object`, класс всё равно от него наследуется.

В нём есть методы, которые есть у любого объекта:
- `toString()` - превращает объект в строку
- `equals()` - проверяет, равны ли два объекта
- `hashCode()` - возвращает число для хранения в хеш-коллекциях
- `getClass()` - возвращает информацию о классе

Часто эти методы **переопределяют**, чтобы они работали правильно.

## 6. Почему класс public final class String помечен как final?

Потому что строки в Java **неизменяемые**. Это очень важно для безопасности и работы программы.

Если бы String не был final, кто-то мог бы написать:
```java
class BadString extends String {
    // и изменить содержимое строки
}
```

Это сломало бы:
- Безопасность (пароли, пути к файлам)
- Работу коллекций (например, HashMap)
- Стринговый пул (JVM кэширует одинаковые строки)

Поэтому String сделали final - чтобы **никто не мог его изменить**.

## 7. Если в Java нет множественного наследования, то почему возможна такая конструкция?

```java
public interface A extends B, C {
}
```

Потому что **интерфейсы - это не классы**. Они не содержат кода и не имеют состояния.

Когда интерфейс A наследуется от B и C, он просто объединяет их методы. Кто реализует A, должен реализовать все методы из B и C.

С классами так нельзя, потому что:
- У них есть код и состояние
- Возникает вопрос: чью версию метода брать, если они совпадают?

С интерфейсами такой проблемы нет - они только "обещают", что методы будут реализованы.
